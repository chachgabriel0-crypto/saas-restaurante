No entra / se frustra — leer esto

1) Mismo proyecto: config.js debe ser la URL y la clave anon de ese Supabase (Settings → API).

2) Rol en SQL: en SQL Editor ejecuta (cambia el correo):

INSERT INTO public.profiles (id, role)
SELECT id, 'super_admin'::public.app_role FROM auth.users
WHERE lower(email)=lower('tu@correo.com')
ON CONFLICT (id) DO UPDATE SET role='super_admin'::public.app_role;

3) Correo confirmado: Authentication → tu usuario → si pide confirmación, ábrelo desde el mail o desactiva “Confirm email” en Auth → Providers (solo desarrollo).

4) Recuperar contraseña: en Supabase → Authentication → URL Configuration, añade tu URL del sitio (ej. https://tudominio.com) y la ruta exacta a super-admin.html en “Redirect URLs”, para que el enlace del correo funcione.

📧 Recuperar contraseña

📋 Alta de usuario para un restaurante

No hay una base por empresa: todos comparten el mismo proyecto Supabase; lo que aísla datos es empresa_id en cada fila y las políticas RLS.

  1. Creá la empresa en Empresas → Nueva empresa.
  2. En Supabase → Authentication → Users: Add user o Invite con el correo real del empleado o admin del local (el mismo que usará en el POS).
  3. Al crearse el usuario, el trigger rellena profiles. Volvé a Usuarios en este panel y pulsá Empresa para asignar restaurante y rol (staff / empresa_admin). Ahí queda vinculado a los datos de su empresa.
  4. Opcional: en Table Editor, profiles.nombre_visible para el nombre que verán en pantalla.
  5. Si no llega el correo de invitación o de restablecer contraseña: spam; Auth → SMTP con proveedor propio; y URL Configuration con la URL de tu index.html en Redirect URLs.
